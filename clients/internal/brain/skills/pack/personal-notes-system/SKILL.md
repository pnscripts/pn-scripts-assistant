# Personal notes system

A notes system is good if the user can capture in seconds and find in under a minute. Keep the structure shallow and the habits small.

## Steps
1. **Ask about use:** what they note (meetings, ideas, study, recipes, work logs), which devices, which app they already use, what frustrates them now. Do not push a new app unless the current one truly fails.
2. **One inbox.** A single place for quick capture on every device (a default note, quick-capture widget, or paper page). Everything goes there first.
3. **Few top-level folders.** A proven simple layout:
   - Projects - things with a goal and an end date.
   - Areas - ongoing responsibilities (health, finances, team, home).
   - Resources - reference topics of interest.
   - Archive - finished or inactive items.
   Avoid deep folder trees; 2 levels are usually enough.
4. **Naming convention.** Dates in ISO format for sortable notes (`2025-03-14 Meeting - Supplier`), clear nouns for topic notes. Decide once, write it down.
5. **Tags sparingly.** A handful of status or type tags (`#idea`, `#todo`, `#waiting`) beat dozens of topic tags. Links between related notes are better than many tags where the app supports them.
6. **Templates** for repeated notes (see below).
7. **Tasks.** Decide where tasks live: in the notes app or in a separate task list. Not both. Actions found in notes get moved to that one place.
8. **Weekly 10-minute cleanup:** empty the inbox into folders, archive finished projects, delete duplicates, add links.
9. **Backup and privacy:** export or sync with backup; keep passwords and sensitive IDs out of ordinary notes, in a password manager instead.

## Meeting note template
```
# 2025-03-14 Meeting - [topic]
People: ...
Purpose: ...
Notes: ...
Decisions: ...
Actions: [ ] who - what - by when
Follow-up date: ...
```

## Idea note template
```
# Idea - [short title]
Problem it solves: ...
First small test: ...
Related: [[link]]
```

## Pitfalls
- Spending more time designing the system than using it.
- Copying a complex setup from the internet that does not match the user's needs.
- Never reviewing; the inbox becomes a second mess.
- Storing secrets in plain notes that sync to many devices.

## Output
The proposed folder structure, naming rules, tag list, 2-3 templates fitted to the user's notes, the capture and weekly cleanup routine, and a migration plan for the existing notes (start small, do not move everything at once).
