# Inbox triage

Decide once per message, act on the important few, and clear the rest. Read only; never send, delete or unsubscribe without the user's explicit OK.

## Steps
1. **Get the batch.** A pasted list or export with sender, subject, date and the first lines is enough to start. Ask about the user's priorities: key people, projects, deadlines this week.
2. **Sweep for risk first.** Flag anything suspicious (unexpected payment requests, changed bank details, password or login alerts, urgent links) for a phishing check before any action. Do not open links.
3. **Group by thread and sender** so one decision covers a whole conversation; the latest message in a thread usually supersedes the earlier ones.
4. **Assign one action to each item** (4D + read later):
   - **Do now** - takes under 2 minutes or is due within 24-48 h.
   - **Delegate** - someone else should handle it; note who.
   - **Defer / schedule** - needs real work; give a date or calendar slot.
   - **Read later** - newsletters, reports, FYI with no ask.
   - **Archive / delete** - no action, already handled, notifications.
5. **Rank the "Do now" list** by deadline, then by who is waiting (manager, client, blocked colleague), then by consequence of delay.
6. **Draft short replies** for the top items: acknowledge, answer or give a date by which you will answer.
7. **Suggest prevention**: filters or rules, unsubscribes, shared mailbox owners. List them as suggestions; the user decides and sets them up.

## Triage table template
| # | From | Subject | Action | Due | Note / draft |
|---|------|---------|--------|-----|--------------|
| 1 | Client A | Contract change | Do now | Today | Draft reply below |
| 2 | Team lead | Budget review | Schedule | Thu | 45 min block |
| 3 | Newsletter | Weekly digest | Read later | - | - |
| 4 | "Bank" | Verify account now | Check for phishing | - | Do not click |

## Example quick reply
"Hi Elena, thanks - I've seen this and will send the revised figures by Wednesday noon."

## Pitfalls
- Answering in arrival order instead of priority order.
- Missing a request buried deep in a long CC thread; scan for the user's name and question marks.
- Treating every "URGENT" in a subject as urgent; check who sent it and why.
- Archiving something that contains a deadline; move the date to a task first.
- Unsubscribing via a link in a suspicious email; use the mail provider's own unsubscribe or block feature.

## Output
Return: the triage table, the ranked "Do now" list with draft replies, items flagged for a phishing check, and optional filter or unsubscribe suggestions. Make clear that nothing has been sent, archived or deleted.
