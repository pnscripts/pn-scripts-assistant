# Game concept document

A concept document answers "what is this game, for whom, and why would they play it instead of something else" - in a form short enough that the team actually reads it.

## Steps
1. **Interview the user:** the idea in their words, what inspired it, platform(s), team size and skills, time and budget, commercial or hobby, any fixed constraints (jam theme, engine).
2. **High concept** - one sentence: "[Genre] where you [core action] to [goal], set in [world/twist]."
3. **References:** 2-3 existing games ("X meets Y") and what is taken from each and what is different.
4. **Target player and platform:** who plays, how long a session lasts, controls (touch, mouse/keyboard, gamepad), offline/online.
5. **Core fantasy and feelings:** what the player should feel (clever, powerful, cosy, scared).
6. **Core loop:** the 30-second action loop and the session-level loop (see the core-loop-and-progression skill for detail).
7. **Key features** - 3-5 only, each tied to the fantasy. Mark the one unique hook.
8. **Art and audio direction:** style in a few words plus reference images the user owns or links to; avoid copying protected art.
9. **Scope:** minimum playable version (vertical slice), content counts (levels, enemies, items), what is explicitly cut.
10. **Business:** price model (premium, free with ads, in-app purchases, free), platform rules that affect it, age rating considerations.
11. **Risks:** technical unknowns, content volume, skills missing, crowded genre.

## One-page template
```
Title (working):
High concept:
Genre / references:
Platform / controls / session length:
Target player:
Core fantasy:
Core loop (30 s / session / long term):
Key features (3-5) - unique hook marked *:
Art and audio direction:
Scope - vertical slice / full game / cut list:
Business model:
Top risks and first test to reduce each:
```

## Example
High concept: "A cosy puzzle game where you repair broken toys by rotating their gears, set in a grandparent's attic." References: gear puzzles + tidy-up games. Hook: each repaired toy unlocks a short memory scene. Vertical slice: 10 puzzles, 2 toy types, 1 memory scene.

## Pitfalls
- Feature lists without a core fantasy; the game feels like a pile of mechanics.
- Scope far beyond the team's time; cut until the slice fits in about a fifth of the schedule.
- Vague claims ("unique gameplay"); state the exact hook.
- Using other games' names, characters or art in the product itself; references belong in the document only.

## Output
The completed one-page concept, a short list of open questions, and the smallest playable prototype the user should build first to test the hook.
