# Работа с Git

Пази работата възстановима. Преди всяка команда, която пренаписва историята или изхвърля промени, провери `git status` и кажи какво ще се загуби.

## Стъпки
1. **Огледай се, преди да действаш.** Изпълни `git status`, `git branch -vv` и `git log --oneline -10`. Трябва да знаеш текущия клон, неподадените промени и колко се различаваш от отдалеченото хранилище.
2. **Започвай работа в отделен клон.**
   ```
   git switch main
   git pull --ff-only
   git switch -c feature/login-form
   ```
3. **Подавай малки, свързани промени.** Прегледай с `git diff`, добавяй съзнателно (`git add -p` за части от файл) и подай с ясно съобщение:
   ```
   Add password strength meter to sign-up form

   Shows weak/medium/strong while typing; blocks submit when weak.
   ```
   Първият ред е до около 50 знака, в повелително наклонение; тялото казва защо. Пиши съобщенията на езика, приет в проекта.
4. **Бъди в крак с основния клон.** `git fetch`, после или `git rebase origin/main` (права история, само за клонове, които никой друг не ползва), или `git merge origin/main` (безопасно за общи клонове).
5. **Разрешавай конфликтите.** Отвори всеки файл, посочен от `git status`, остави правилните части между `<<<<<<<`, `=======` и `>>>>>>>`, махни маркерите, пусни тестовете, после `git add` за файла и `git rebase --continue` или `git commit`. За да се откажеш: `git rebase --abort` или `git merge --abort`.
6. **Изпрати и отвори заявка за сливане.** `git push -u origin feature/login-form`. След пребазиране на собствения си клон използвай `git push --force-with-lease`, никога обикновено `--force`.
7. **Почисти след сливането.** `git switch main && git pull --ff-only && git branch -d feature/login-form`.

## Рецепти за отмяна
| Положение | Команда |
|---|---|
| Изхвърляне на промените в един файл | `git restore file.txt` |
| Изваждане на файл от подготвените | `git restore --staged file.txt` |
| Поправка на последното съобщение или забравен файл (неизпратено) | `git commit --amend` |
| Отмяна на последното подаване, промените остават | `git reset --soft HEAD~1` |
| Безопасна отмяна на вече изпратено подаване | `git revert <hash>` |
| Подадено в main вместо в клон | `git branch new-branch`, после `git reset --hard origin/main` в main (след като провериш, че нищо друго не се губи) |
| „Изгубено“ подаване след reset или rebase | `git reflog`, после `git switch -c rescue <hash>` |
| Временно отлагане на работа | `git stash push -m "wip"`, по-късно `git stash pop` |

## Капани
- Никога не пренаписвай историята (`rebase`, `reset`, `amend`, принудително изпращане) на клон, който други вече са изтеглили.
- `git reset --hard` и `git clean -fd` трият неподадената работа завинаги; първо потвърди с потребителя.
- Никога не подавай тайни (`.env`, ключове, пароли). Ако такава е изпратена, смени я веднага; изтриването на файла не я маха от историята.
- Добави резултатите от компилация, зависимостите и файловете на редактора в `.gitignore` преди първото подаване.
- Откъснатият HEAD е безвреден, докато не подадеш нещо; създай клон (`git switch -c name`), за да запазиш тази работа.
- Командите и поведението по подразбиране се различават леко между версиите на Git; провери `git --version` и официалната документация, ако нещо се държи неочаквано.

## Резултат
Върни точните команди по ред с по едно изречение обяснение, предупреждение преди всяка разрушителна стъпка и как да се провери резултатът (`git status`, `git log --oneline --graph`).
