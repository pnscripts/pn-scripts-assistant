# Compare documents

Show differences that matter, not every comma. Be exact about what each document says and keep the user's goal in view (sign, choose, approve, review).

## Steps
1. **Identify the documents.** Name each one (A, B, C) with title, version or date and author. Confirm which is the older or baseline version, if any.
2. **Clarify the purpose.** Version review (what changed) or choice (which is better for the user)? Ask for the user's priorities when choosing: price, terms, risk, quality, speed.
3. **Align the structure.** Match sections or clauses even when numbering or order differs. Note sections that exist in only one document.
4. **Compare section by section.** For each matched part, mark: unchanged, added, removed, reworded (same meaning), changed meaning.
5. **Rate the impact** of each change: high (money, obligations, deadlines, liability, rights), medium, low (wording, formatting).
6. **Compare key terms in a table** for offers and specs: price, what is included, duration, payment terms, cancellation, warranty, support, penalties.
7. **Conclude.** For version review, list high-impact changes first. For a choice, rank the options against the user's priorities and say what is still unknown.

## Template
```
Documents: A = <title, date>  B = <title, date>

High-impact changes
| Section | A says | B says | Impact |
|---|---|---|---|
| Payment | 30 days | 14 days | Cash needed sooner |

Other changes: ...
Only in A: ...   Only in B: ...
Conclusion: ...
Questions to ask the other party: ...
```

## Example
Two quotes for a website: A is cheaper but excludes hosting and limits revisions to one round; B costs more but includes one year of hosting and three revision rounds. With hosting added, the total cost difference shrinks to a small amount; recommend asking A for a revision-round price before deciding.

## Checklist
- [ ] Each document identified with its date or version
- [ ] Numbers compared in the same unit, currency and period, with or without VAT stated
- [ ] Removed text noticed, not only added text
- [ ] Definitions compared too; a changed definition changes every clause using it
- [ ] Quotes from each document are exact

## Pitfalls
- Trusting a supplied "summary of changes" instead of checking the text.
- Missing small words that change meaning: "may" vs "shall", "and" vs "or", "including" vs "limited to".
- Comparing prices that cover different scopes.
- Scanned files may hide changes in recognition errors; flag unreadable parts.
- For contracts, add that the comparison is not legal advice and a lawyer should review high-impact clauses.

## Output
Hand back the comparison in the template: high-impact differences first, a side-by-side table for key terms, items present in only one document, a conclusion tied to the user's goal and questions to raise.
