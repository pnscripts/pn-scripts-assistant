# Проектиране на бази данни и SQL

Първо опиши реалните неща и връзките между тях, после пиши заявките според този модел. Всяка промяна на работещи данни е рискова: резервно копие, проба върху копие, транзакции.

## Стъпки при проектиране
1. **Изброй обектите и фактите.** Съществителните стават таблици (клиент, поръчка, продукт), фактите — колони, а глаголите между тях — връзки.
2. **Избери ключове.** Всяка таблица има първичен ключ (`id` — автоматично цяло число или UUID). Външните ключове пазят връзките (`orders.customer_id → customers.id`).
3. **Опиши връзките.** Едно към много: външен ключ от страната на „много“. Много към много: свързваща таблица (`order_items(order_id, product_id, quantity)`).
4. **Нормализирай, за да няма повторения.** Един факт на едно място: без колони `phone1, phone2, phone3` (ползвай подчинена таблица), без адреса на клиента, копиран във всяка поръчка, освен ако не е нарочен исторически запис.
5. **Избери типове и ограничения.** `NOT NULL` за задължителните, `UNIQUE` за имейли или кодове, `CHECK (quantity > 0)`, точен `DECIMAL(12,2)` за пари (никога число с плаваща запетая), време с часова зона в UTC.
6. **Планирай индексите.** Първичните и уникалните ключове вече са индексирани; добави индекси за външните ключове и за колоните, които често се ползват в `WHERE`, `JOIN` и `ORDER BY`. Редът в съставния индекс има значение: първо колоните с равенство, после тези с диапазон.

## Примерна схема
```sql
CREATE TABLE customers (
  id         BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email      VARCHAR(255) NOT NULL UNIQUE,
  name       VARCHAR(200) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE orders (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id BIGINT NOT NULL REFERENCES customers(id),
  total       DECIMAL(12,2) NOT NULL CHECK (total >= 0),
  placed_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX orders_customer_placed ON orders (customer_id, placed_at);
```
(Синтаксис на PostgreSQL; за други системи промени типовете за автоматичен ключ и за време.)

## Примерна заявка
Десетте клиенти с най-голяма сума на покупките от 1 януари 2026 г.:
```sql
SELECT c.name, COUNT(o.id) AS orders, SUM(o.total) AS spent
FROM customers c
JOIN orders o ON o.customer_id = c.id
WHERE o.placed_at >= '2026-01-01'
GROUP BY c.id, c.name
ORDER BY spent DESC
LIMIT 10;
```

## Търсене на грешки в заявки
1. Поискай системата и версията, дефинициите на таблиците и няколко примерни реда.
2. Твърде много редове: съединение по неуникален ключ умножава редовете; провери условията на съединението, първо обобщи в подзаявка.
3. Липсващи редове: `INNER JOIN` изпуска редовете без съвпадение, а условие в `WHERE` върху дясната таблица превръща `LEFT JOIN` във вътрешно съединение; премести условието в `ON`.
4. Изненади с `NULL`: `= NULL` никога не е вярно, ползвай `IS NULL`; `NOT IN` със `NULL` в списъка не връща нищо, ползвай `NOT EXISTS`.
5. Бавна заявка: пусни `EXPLAIN` (или `EXPLAIN ANALYZE` върху копие); търси пълно обхождане на големи таблици, липсващи индекси, функции върху индексирани колони (`WHERE LOWER(email) = ...` иска индекс по израз), `SELECT *` върху много колони.

## Безопасни промени на работещи данни
- Първо резервно копие и ясен начин за възстановяване.
- Преди `UPDATE` или `DELETE` пусни `SELECT` със същото `WHERE` и провери броя редове.
- Работи в транзакция: `BEGIN; UPDATE ...; -- проверка; COMMIT;` или `ROLLBACK;`.
- Ползвай миграции под контрол на версиите; добавяй колоните като незадължителни или със стойност по подразбиране, попълни ги, после добави ограниченията.

## Капани
- Сглобяването на SQL от низове с данни от потребителя отваря SQL инжекции; винаги ползвай параметризирани заявки.
- Списъци, разделени със запетая, в една колона правят търсенето и целостта невъзможни.
- Твърде много индекси забавят записа; индексирай за истинските заявки, не „за всеки случай“.
- Системите се различават (автоматични ключове, „вмъкни или обнови“, функции за дати, `LIMIT` срещу `TOP`); казвай за коя е написан SQL кодът.

## Резултат
Върни схемата или заявката като изпълним SQL за системата на потребителя, кратко обяснение как работи, очаквани резултати или брой редове за проверка и нужния индекс или предпазна стъпка, преди да се пусне върху истински данни.
