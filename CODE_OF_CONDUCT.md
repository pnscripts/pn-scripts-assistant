# Code of conduct

This is a small project. The rule is short because a long one would not be
read, and because the long ones are usually written after something went wrong
rather than before.

## What is expected

Be decent to people. Assume the person you are replying to is trying to help
and has less context than you do. Disagree about the work — sharply, if it
matters — and not about the person doing it.

Concretely, and these are the things that actually happen in issue threads:

- **Criticise the code, the claim or the decision.** Not the competence of
  whoever wrote it.
- **Take "no" without a campaign.** A maintainer declining a feature is
  allowed, and the reason will be given.
- **Do not post somebody's private information**, and do not post somebody
  else's data while reporting a bug — this program reads people's files, so a
  log or a screenshot is worth a glance before it is attached.
- **No harassment, of any kind, anywhere the project is.** Issues, pull
  requests, commit messages, email.

## What happens when somebody does not

The maintainer will say so once, plainly. If it continues, the comment is
removed and the account is blocked from the repository. There is no committee
and no appeal process; there is one person, and this is what one person can
honestly promise to do.

## Reporting

Email **petar.v.nikolov@gmail.com**, with `pn-scripts-assistant` in the
subject. If the problem is with the maintainer, say so in the issue and it will
be answered in public.

Security problems are not a code-of-conduct matter — see
[SECURITY.md](SECURITY.md), and please do not report them in public.
